## 🧭 개발 규칙

### CLAUDE.md 작성 규칙

- **목적:** Claude Code 환경에서 **Vibe Coding**을 원활히 하기 위한 문서입니다.
- **작성 원칙:**
  - Claude에게 전달할 정보만 포함합니다.
  - 개인 설정, 실험 코드, 불필요한 메모 등은 포함하지 않습니다.
  - 문서는 프로젝트 루트 경로에 위치해야 합니다.

---

### 브랜치 전략

- **작업 원칙:** 모든 개발은 `main`, `dev` 브랜치를 제외한 **개인 전용 브랜치**에서 진행해야 합니다.
- **브랜치 명명 규칙:**
  - 개인 이름을 그대로 사용합니다.
  - 예시:
    ```bash
    git checkout -b chanyeong
    ```
- **병합 규칙:**
  - 개인 브랜치 → `dev` → `main` 순으로 병합합니다.
  - Pull Request 시 코드 리뷰를 거친 뒤 승인 후 병합합니다.

---

### 작업 할당

- **작업 관리:** 모든 개발 작업은 **Sprint Project** 내에서 **Issue**로 생성하여 담당자에게 할당합니다. (Issue는 최소 기능 단위로 작성)
- **주차별 계획:** 각 주차에 수행할 작업은 미리 정의하며, Sprint 시작 전 계획을 명확히 설정합니다.
- **추가 작업:** 새로 발생하는 작업은 Issue를 추가하여 관리합니다.
- **커밋 규칙:** 커밋 시 반드시 해당 작업의 Issue 번호를 링크합니다.
  - 예시: `git commit -m "로그인 기능 구현 #1"`
- **PR merge 시 Issue 닫기:** PR 메시지에 `Closes #Issue번호`를 포함하면 merge 후 자동으로 Issue가 닫힙니다.
  - 예시: `Closes #1`
- **작업 완료 보고:** Issue가 완료되면 상태를 `Done`으로 업데이트하고, PR 생성 시 리뷰어에게 알립니다.
